# Register Elicitation

Expands SKILL.md Stage 1. This is the one project-level decision RCE-1 requires be made deliberately rather than defaulted (Rule 9) — everything else in the standard applies regardless of where the project sits on the spectrum.

## Why this is sequenced the way it is

Asking "jargon or natural English?" cold, before the user has seen any output, produces an answer disconnected from what they're actually looking at. People calibrate register preference against a concrete example far more reliably than against an abstract question. Hence: draft first in the safe default, then ask, then lock.

## Step 1 — Draft natural-English-first

For the first rule of a new project, write it in plain, ordinary English with minimal jargon — readable at a glance by someone who has never seen this game. This is not a placeholder to be discarded; it may well be the final register if the user confirms it.

## Step 2 — Elicit

After the user has seen that first draft, ask one direct question. Do not bundle this with unrelated questions.

Suggested phrasing: *"That's drafted in plain English with light jargon. D'you want to push it more toward keyword-heavy shorthand — think Magic the Gathering or 40k — or keep it close to how it reads now?"*

Acceptable answers and what they mean:
- **Keep it natural** → register locked, low jargon, proceed.
- **More jargon-forward** → ask a brief follow-up on which mechanics deserve keywords first (usually the ones expected to recur or interact), then proceed.
- **Somewhere in between / show me another example** → draft a second passage at a different point on the spectrum, then ask again. Do not lock on an unresolved answer.

## Step 3 — Lock as a project setting

Once confirmed, record the register decision as its own entry in the project SWD (category: project setting, not lexicon/keyword) so it persists across the whole drafting session and any future session that reopens the same project. Do not re-run this elicitation for every subsequent rule in the same project — that's the entire point of locking it.

If the user explicitly changes their mind mid-project ("actually, let's push this more jargon-heavy from here"), update the SWD entry and note the change, rather than silently drifting register rule by rule without recording why.

## Edge case — user states register up front

If the user opens with an explicit register preference before any drafting happens ("I want this keyword-heavy like 40k" or "keep everything plain English, no jargon at all"), skip Step 1's natural-English default draft — that default exists to give an undecided user something concrete to react to, not to override a decision already made. Go straight to Step 3 and lock what they stated.
